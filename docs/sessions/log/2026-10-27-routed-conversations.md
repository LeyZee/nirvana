# 2026-10-27 — Prérequis EQ-08 et EQ-10 : un chatteur n'atteint que les conversations routées — done
Fait : migration 0016 (`conversations.routed_to_user_id`, nullable, index partiel). `requireRole` lit l'appartenance par `withMember` : un membre de l'équipe au scope `self` voit ses `creator_ids` passer dans `routedCreatorIds` (contrat `CurrentUser`), ce qui ferme d'un coup toutes les routes qui vérifient `creatorIds` (Dashboard, fans, persona, conversations). `conversations` lui ouvre seulement les conversations qui lui sont routées : liste filtrée, lecture, messages, journal, valider, refuser, prendre et rendre la main ; autre conversation → 403 `conversation_forbidden` ; le mode reste réservé à qui tient toute la créatrice. Un `operator` sans fiche d'équipe garde le comportement d'avant.
Pas fait : l'écriture de `routed_to_user_id` (EQ-08) ; l'ouverture pendant le shift (EQ-13, ADR 0025 en cours d'écriture).
Décisions : garde du serveur plutôt que RLS, calculée à chaque requête. EQ-13 n'aura qu'à remettre dans `creatorIds` les créatrices couvertes par un shift actif ; rien ici ne l'en empêche.
Découvertes : les routes de lecture de `conversations` acceptent le rôle `creator` (PR suivante, à part).
Candidats à suppression : aucun.
Vérifié : pnpm check ✓, pnpm test ✓ ; intégration `apps/api` (138 tests, dont `conversations-http.integration.test.ts` : chatteur limité à sa conversation routée, 403 sur les autres, sur le mode et le Dashboard, prise et reprise de la main ; manager actif sur toutes).
